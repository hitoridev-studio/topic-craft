Factorio の乱数は、3回見れば次が全部わかる

Factorio が使う乱数生成器 taus88 を、ゲームの実装と同じ式で JavaScript に書いた。出力を3つ観測しただけで 88bit の内部状態を復元し、先の値を全部当てる。

#予測実際

仕組み

Factorio の RandomGenerator::getInt() は、3本の線形帰還シフトレジスタ（LFSR）を独立に進めて XOR したものを返す。Boost.Random の taus88 と同じ生成器で、元開発者がフォーラムでそう答えている（元記事が 2014 年の投稿を引き、逆コンパイルで確かめている）。このページの実装は、元記事が示した逆コンパイル形と Boost の定義形の両方を書き、ランダムな状態 2,000 個 × 10 ステップで全ビットが一致することをテストしてから使っている。

// Factorio の getInt()（逆コンパイル形を JavaScript に写した）
a = (((a << 12) ^ (a >>> 6)) & 0x1fff) ^ (a >>> 19) ^ (a << 12)
b = (((b << 4)  ^ (b >>> 23)) & 0x7f)   ^ (b >>> 25) ^ (b << 4)
c = (((c << 17) ^ (c >>> 8)) & 0x1fffff) ^ (c >>> 11) ^ (c << 17)
return a ^ b ^ c

シフトと XOR と定数マスクしか使っていないので、出力の各ビットは内部状態のビットの GF(2) 上の線形結合 になる。3本のレジスタは 31・29・28 bit（合計 88 bit）しか効いておらず、下位の 1・3・4 bit は1回進めると消える。だから 32bit の出力を3つ（96 本の式）観測すれば、88 個の未知数が全部決まる。

未知数88 bit（seed1 の上位 31 bit、seed2 の上位 29 bit、seed3 の上位 28 bit） 式観測1つにつき 32 本。3つで 96 本、階数 88 解き方基底ベクトル ei を入れて3回進めた出力を集めると行列の第 i 列になる。あとは GF(2) のガウスの消去法。96×96 のビット行列で 1 ms 未満 候補の数観測 0 回 288 → 1 回 256 → 2 回 224 → 3 回で 1 通り

復元した状態からは、ゲーム側と同じ式を回すだけで、以後の出力が順に出る。ゲームが乱数を使う場面（クラフトの品質、ウラン処理の当たり、掘削のおまけ）は、この出力を閾値と比べているだけなので、出力が分かれば結果も分かる。

注意

このページは「32bit の出力がそのまま3つ見える」前提で復元している。ゲームの中では出力そのものは見えず、元記事はレシピの結果（出たか、出なかったか）から上位ビットを少しずつ集めて 88 回分の観測で復元し、その計算をゲーム内の回路（コンビネータ）で組んでいる。そこが元記事の本題で、このページはその土台の数学を動かして見せるもの。

Factorio 2.1 では乱数の使われ方が変わり、元記事のゲーム内の仕掛けは動かなくなった。生成器そのものは変わっていないので、このページの復元はそのまま成り立つ。
